# Web Push Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Ship web-only MuntiCares with opt-in browser push for calls, messages and booking/status updates.
**Architecture:** Browser subscriptions and a push-only service worker; Supabase authenticated subscription management, database event queue and server delivery with VAPID.
**Tech Stack:** React, browser Push API, Supabase Postgres/Edge Functions, web-push.
**Spec:** ../specs/2026-11-18-web-push-design.md

## Global constraints
- Web-only; no Capacitor, Android build or Firebase integration.
- Generic notification previews; authenticated account ownership; no auto-answer.
- Preserve unrelated working-tree edits and historical database migrations.

## Review focus
- Shared browser account changes must detach the prior subscription.
- Denied/unsupported permission must preserve in-app notifications.
- Expired calls must not ring; notification links stay on the app origin.
- Retry transient delivery errors without retaining dead subscriptions.
- Server requests cannot select arbitrary recipients or push URLs.

## Tasks
1. Remove Android/Capacitor runtime and dependencies; simplify auth redirects, browser networking and tracking. Verify imports, browser redirect tests and build.
2. Add tested browser subscription lifecycle, opt-in control, service worker and manifest. Test permission denial, logout cleanup, worker click routing and generic previews.
3. Add subscriptions, database event outbox and protected Edge delivery function. Test event targeting, endpoint validation, delivery error handling and stale calls. Trigger from requests/messages/calls, not client-side notification polling.
4. Configure secrets and deploy where authenticated tooling permits. Verify schema policies and endpoint authorization, run relevant tests/build/lint, and document remaining device/hosting checks.
